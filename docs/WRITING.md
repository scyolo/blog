# 写作与发布

## 新建文章

将 templates/post.md 复制到 src/content/posts/，文件名建议使用英文。先修改 slug、标题、摘要和日期，再写正文。slug 必须以小写英文字母开头，只能包含小写字母、数字和连字符，同一篇文章发布后保持不变；文件移动或标题修改不会改变文章地址。

category 只使用 knowledge（知识笔记）或 essay（随笔）。tags 用于更细的主题。时间必须带 Z 或明确时区，推荐使用带引号的 ISO 时间，例如 '2026-10-03T09:00:00+08:00'，页面显示使用北京时间。

每篇文章都必须显式写 draft。草稿使用 true，正式发布才改为 false；缺失字段不会被当作已发布。未来日期文章需要到期后再次构建才会出现，不提供自动定时发布。

## 本地检查

使用项目指定的 Node 与 pnpm，运行 pnpm dev 写作。提交前运行 pnpm validate:content、pnpm test 与 pnpm build，再使用 pnpm preview 检查真实构建，尤其是全文搜索。开发服务器不提供新生成的 Pagefind 索引，不应据此判断搜索故障。

## 图片与附件

文章封面和正文图片放在 src/assets/images，使用相对路径引用。例如位于 src/content/posts/example.md 的文章，可以写：

```markdown
![清楚说明图像内容的替代文本](../../assets/images/example.svg)
```

图片应先压缩，不把相机原图或视频塞入 Git。图片所在目录均视为可公开，不存放未获授权素材或保密附件。public 会原样进入站点产物，不得放入 .env、密钥、Markdown 源文档或其他私密文件。私有仓库和 draft 不是附件访问控制。

不支持直接热链远程图片，不支持在 Markdown 中插入原始 HTML；请使用标准 Markdown、代码块、公式或 Mermaid。SVG 必须是可信的自有图形，不导入来历不明的可执行内容。

## 技术内容

代码使用带语言名的围栏；公式采用 KaTeX 支持的语法，行内使用 $...$，独立公式使用 $$...$$。不支持完整 LaTeX/TikZ 工程。

流程图、时序图和分组架构图使用 mermaid 围栏。图表资源从本站加载，接近视口才渲染；异常时仍能查看源代码。复杂图可使用本地 SVG/PNG/WebP。建议添加 Mermaid 的 accTitle 与 accDescr，帮助辅助技术理解图表。

## 公开前的人工确认

- 内容、图片和引用均可公开，示例不冒充真实经历。
- 标题、摘要、时间、分类和唯一 slug 正确。
- 公式、代码、图表和图片已在手机宽度检查。
- Git 中没有密钥、私人附件和不应公开的资料。
- 设置 draft: false 后，等待所有检查通过和部署成功，再检查正式地址、搜索和 RSS。

## 修改与下架

更新正文时保留 slug，需要时填写带时区的 modDatetime。修改旧文不会把它变成一篇新发布文章。

普通下架可以改回 draft: true 后重新发布。历史部署、RSS 客户端、搜索缓存和读者副本可能仍保留旧内容；敏感撤回需要额外检查历史部署与公开附件，不能承诺清除所有外部副本。回滚前排除含有已撤回内容的旧版本。

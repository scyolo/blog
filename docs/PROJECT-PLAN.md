# 个人博客项目计划书 V2.0

## 内容优先、轻量维护、发布可控

本方案完整替代前一版，保留已确认的博客定位，重点修正发布控制、内容保护、成本预算、排期与验收方式。

---

## 一、目标、范围与技术决策

### 1.1 项目目标

建设一个兼顾以下用途的个人博客：

- **知识沉淀**：技术文章、学习笔记，支持代码、公式和图表。
- **随笔写作**：适合长文与图文表达，保证中文阅读体验。
- **个人展示**：提供个人介绍、项目作品和联系入口。

成功标准是：**作者能够持续、顺畅地写作和发布，读者能够方便地查找、舒适地阅读内容。**

### 1.2 建设约束

| 项目       | 确定方案                                   |
| ---------- | ------------------------------------------ |
| 开发投入   | 单人，每周 8–12 小时                       |
| 排期基准   | 按每周约 10 小时、8 周编排，约 80 小时     |
| 时间分配   | 约 64 小时实施与验证，另留 16 小时机动时间 |
| 写作方式   | 本地 Markdown + Git                        |
| 视觉方向   | 首页适度卡片化，文章页阅读优先             |
| 语言与时区 | 简体中文，`zh-CN`，`Asia/Shanghai`         |
| 托管目标   | 免费额度内运行，不默认购买域名或服务       |
| 仓库       | 独立的私有 GitHub 仓库                     |
| 发布控制   | 检查通过后发布同一份构建产物               |

八周是目标而非保证。若持续只能投入每周八小时，或关键验证超出预算，按任务顺序顺延，不通过省略内容安全、公式或图表支持来换取日期。

### 1.3 首版范围

| 必须完成                         | 可以后置                 | 首版不建设               |
| -------------------------------- | ------------------------ | ------------------------ |
| 首页、文章列表与详情、关于页     | 多套文章布局             | 数据库、管理后台         |
| 知识与随笔栏目、标签、归档       | 系列文章、相关文章推荐   | 用户账号、评论、点赞计数 |
| 基础项目展示页                   | 复杂首页精选模块         | 邮件订阅系统             |
| 代码、表格、公式、流程图与架构图 | 高级图表交互和装饰性动效 | 在线绘图编辑器           |
| 中文搜索、RSS、基本 SEO          | 动态生成分享图片         | 复杂交互式文章组件       |
| 响应式、暗色模式、基础无障碍     | 独立域名及其他托管平台   | 自动定时发布             |
| 受控发布、备份与撤稿流程         | 完整多浏览器自动化矩阵   | 网站访问统计服务         |

### 1.4 开源复用与技术栈

采用 **AstroPaper + Astro + TypeScript + Tailwind CSS**。

- 以已调研的 [AstroPaper v6.1.0](https://github.com/satnaing/astro-paper/releases/tag/v6.1.0) 为验证起点，复现锁文件、处理必要安全更新后固定项目基线。
- 借鉴 [Fuwari](https://github.com/saicaca/fuwari) 的图文展示方式，不引入整套主题或额外的 Svelte 技术栈。
- 借鉴 [Hugo PaperMod](https://github.com/adityatelange/hugo-PaperMod) 的低干扰阅读设计。
- 借鉴 [Tailwind Next.js Starter Blog](https://github.com/timlrx/tailwind-nextjs-starter-blog) 的技术文章与作品组织方式，不引入 Next.js。

保留上游许可证和来源说明。示例文章、人物资料、图片与品牌信息不得直接作为个人正式内容发布。

## 二、产品、内容与阅读方案

### 2.1 页面结构

| 页面       | 首版实现                                       |
| ---------- | ---------------------------------------------- |
| 首页       | 简短个人介绍、最新文章卡片、项目入口           |
| 文章列表   | 时间倒序、分页、知识与随笔栏目                 |
| 文章详情   | 标题、摘要、日期、标签、目录、正文、前后篇导航 |
| 标签与归档 | 标签聚合、按年份归档                           |
| 项目展示   | 标题、简介、技术栈、仓库或演示链接、可选封面   |
| 关于       | 个人介绍、关注方向、邮箱与社交链接             |
| 搜索       | 已发布文章的标题与正文全文搜索                 |
| 辅助页面   | 404、RSS、站点地图                             |

初期不同时堆叠“精选文章”和“最新文章”等重复模块。文章较少时仍应自然完整；无项目或无搜索结果时提供明确的空状态。

### 2.2 视觉与阅读约定

- 使用中性底色和低饱和蓝色强调，统一管理颜色、字体与间距。
- 首页保留卡片表达，但不使用全屏横幅或重型转场。
- 封面可选，没有封面的文章采用文字卡片。
- 正文最大宽度约 760px，基础字号约 18px，行高约 1.8。
- 桌面端侧边目录，移动端折叠目录。
- 代码、表格、公式和宽图在自身容器内滚动，不撑破页面。
- 主题遵循系统偏好，也允许手动切换并记住选择。
- 中文优先使用系统字体，必要字体和脚本随站点部署，不依赖外部字体 CDN。
- 提供键盘焦点、可理解的按钮名称及减少动画支持。

### 2.3 内容接口与永久链接

文章沿用 Astro 内容集合，保留标题、摘要、日期、标签等基础字段，明确以下约定：

| 字段                   | 约定                                           |
| ---------------------- | ---------------------------------------------- |
| `slug`                 | 显式、全局唯一的英文永久标识，用于生成文章地址 |
| `title`、`description` | 标题与摘要，正式发布前必须有效填写             |
| `pubDatetime`          | 带时区的发布时间                               |
| `modDatetime`          | 可选修改时间                                   |
| `draft`                | 必须显式声明，新文章模板默认 `true`            |
| `category`             | `knowledge` 或 `essay`                         |
| `tags`                 | 标签列表                                       |
| `cover`                | 可选封面                                       |

通过 Astro 内容加载器的 ID 配置使用 `slug`，文章地址固定为 `/posts/<slug>/`，不依赖标题或文件所在目录。发布后原则上不修改；确需修改时，必须同时维护旧地址重定向。

项目使用独立的 Markdown 内容集合，包含标题、简介、技术栈、可选封面及仓库／演示链接。首版仅做展示卡片，不制作独立项目详情页。

**不新增业务 REST API。**公开接口主要是文章永久链接、栏目页面、RSS 和站点地图。

### 2.4 发布状态与附件边界

- 本地开发允许预览草稿和未来文章。
- 生产环境只生成显式 `draft: false`，且发布时间不晚于本次构建时间的文章。
- 缺失发布状态、重复 `slug` 或无效时间时阻止构建。
- 使用统一构建时间，不保留主题可能存在的提前发布时间容差。
- 未来文章不会到点自动出现，需重新触发构建。
- 草稿正文不得进入生产 HTML、搜索索引、RSS、归档或站点地图。

**附件单独管理：**

- `public` 及站点资源目录中的文件一律视为准备公开的资源。
- 尚不能公开的附件不进入这些目录；保密材料不进入博客工程。
- 私有仓库和 `draft` 字段都不是附件访问控制机制。
- 验收同时检查页面、索引和构建产物，不能只检查文章地址是否 404。

### 2.5 技术内容支持

| 内容                   | 实现与边界                                                     |
| ---------------------- | -------------------------------------------------------------- |
| 代码                   | 使用 Astro/Shiki，提供复制按钮与宽内容滚动                     |
| 表格                   | 支持 Markdown 表格，移动端容器滚动                             |
| 公式                   | `remark-math` + `rehype-katex`，构建期渲染，本地部署字体与样式 |
| 流程图、时序图、架构图 | Mermaid；架构图优先采用稳定的分组节点与连线语法                |
| 复杂插图               | 支持本地 SVG、PNG、WebP，不建设绘图编辑器                      |
| 图片                   | 合理尺寸、宽高信息、替代文本，非首屏图片延迟加载               |

公式支持范围以 KaTeX 兼容语法为准，不承诺运行完整 LaTeX 或 TikZ。

Mermaid 仅在含图表的页面、图表接近视口时加载，使用严格安全模式。支持主题切换后的重新渲染；失败时保留源码与提示，不影响正文。必须验证中文标签与宽架构图的实际可读性。

搜索采用支持中文分词的 Pagefind，仅索引已发布文章；RSS 输出摘要和原文链接。分享图使用文章封面或站点默认图，首版不生成动态 OG 图片。

## 三、工程、发布与恢复机制

### 3.1 第一周先验证关键组合

在大规模定制前，用公开测试样文完成以下验证：

1. Windows 安装、启动和生产构建。
2. 中文、代码、公式、Mermaid 与 Pagefind 可以共同工作。
3. Linux CI 可以使用相同锁文件构建。
4. 构建产物可以上传 Cloudflare Pages。
5. 在作者常用宽带与移动网络上访问正文、图片、搜索和图表资源。

同步处理上游构建脚本的 Windows 兼容问题，移除远程字体获取等不必要依赖。

验证不通过时，先解决阻塞问题，不继续大面积改造页面。托管访问不满足需要时，不擅自开通付费服务；保留本地开发成果，再调整部署安排。

### 3.2 单一生产发布链

使用 **Cloudflare Pages Direct Upload + GitHub Actions**：

```text
本地写作与预览
       ↓
提交到 GitHub
       ↓
格式、类型、内容规则与单元测试
       ↓
清洁构建静态站点与 Pagefind 索引
       ↓
对这份产物运行端到端测试及产物检查
       ↓
确认仍为 main 最新提交
       ↓
通过 Wrangler 上传同一份 dist
       ↓
线上冒烟检查
```

固定规则：

- 不启用另一条独立的 Cloudflare 生产自动构建流程。
- PR 执行检查，但默认不创建公开云端预览，不使用部署密钥。
- `main` 检查全部通过才可以部署；测试失败时线上版本不变。
- 部署前不再次构建，避免测试版本与上线版本不同。
- 生产发布串行执行，避免旧任务覆盖新版本。
- 搜索与端到端验收基于生产构建，不基于开发服务器。
- 每次构建从干净产物开始，避免旧搜索索引或文件遗留。

本地提供统一的开发、检查、测试、构建和预览命令。搜索需要重新构建索引的行为写入作者指南。

部署依据：[Cloudflare 持续集成直接上传说明](https://developers.cloudflare.com/pages/how-to/use-direct-upload-with-continuous-integration/)。

### 3.3 工具链与凭据

- 使用 Node 22 LTS 的受支持安全补丁版本、pnpm 10，固定本地与 CI 版本。
- 使用锁文件安装；依赖更新通过独立变更验证。
- 单元测试使用 Vitest，端到端测试使用 Playwright，无障碍自动检查使用 axe。
- GitHub Actions 权限默认最小化。
- Cloudflare Token 仅在部署步骤提供，限制到所需账户与 Pages 权限，不使用全局 API Key。
- 密钥不写入代码、文章、构建产物或公开环境变量。

不依赖免费私有仓库未必具备的付费分支保护能力来保证发布安全。

### 3.4 日常写作流程

1. 从文章模板创建草稿，填写元信息。
2. 本地撰写和预览，检查图片、公式及图表。
3. 确认内容和附件可以公开。
4. 将 `draft` 改为 `false`，提交变更。
5. 查看 CI 与部署结果，失败时依据错误说明修复。
6. 发布成功后检查正式地址、搜索和 RSS。

交付指南必须覆盖这条完整流程，而不仅是列出终端命令。

### 3.5 下架、紧急撤回与回滚

| 情况         | 处理流程                                                             |
| ------------ | -------------------------------------------------------------------- |
| 普通下架     | 更新内容状态，重新发布，确认当前页面、索引和订阅输出已移除           |
| 敏感内容撤回 | 同时检查历史部署、公开附件、相关缓存和构建产物；处理可控范围内的副本 |
| 错误版本发布 | 恢复已知安全的成功部署，再修复或回退源代码                           |

历史预览部署可能继续通过独立地址访问。回滚前检查目标版本是否包含已经撤回的内容，不能只按“上一个版本”机械恢复。

不承诺删除搜索引擎、RSS 阅读器或他人保存的外部副本。

## 四、排期、优先级与交付

### 4.1 八周里程碑

| 阶段    | 核心任务                                                           | 通过条件                                   |
| ------- | ------------------------------------------------------------------ | ------------------------------------------ |
| 第 1 周 | 固定基线、关键内容试跑、Windows/Linux 验证、测试部署与实际网络检查 | 核心技术组合可用，无未解决的基础阻塞       |
| 第 2 周 | 内容集合、永久链接、发布状态、栏目及附件规则                       | 草稿、未来文章、重复标识和公开产物测试通过 |
| 第 3 周 | 首页卡片、文章列表、项目与关于页、基础响应式                       | 内容少时页面仍完整，主要导航可用           |
| 第 4 周 | 中文排版、目录、代码、公式、图表与图片体验                         | 综合样文在亮暗主题和手机上可读             |
| 第 5 周 | 中文搜索、标签归档、RSS、元信息与站点地图                          | 内容出口一致，检索结果正确                 |
| 第 6 周 | 完整 CI 发布链、端到端测试、作者写作验收                           | 形成可日常使用的候选版本                   |
| 第 7 周 | 性能、无障碍、浏览器兼容与问题修复                                 | 发布阻塞项清零，优化目标有实测结果         |
| 第 8 周 | 操作指南、恢复与撤回演练、正式内容检查、发布交付                   | 发布与恢复流程均可重复执行                 |

检查和测试随对应功能一起增加，不集中到最后两周。第一周的临时测试部署也只能使用明确可公开的样文。

### 4.2 超期时的固定取舍顺序

先推迟：

1. 装饰性动效及额外配色。
2. 复杂精选模块、额外文章布局。
3. 自动化浏览器矩阵扩展，改为发布前人工补充验证。
4. 已明确列为后置的功能。

不得省略：

- 草稿与附件边界；
- 测试通过后才发布的控制；
- 代码、公式、流程图和架构图支持；
- 移动端基本可读性；
- 作者完整写作流程和恢复说明。

若必须完成项仍超出时间预算，则顺延，不将未验证功能标记为完成。

### 4.3 最终交付物

- 可维护的博客源码及上游修改说明。
- 正式站点与受控发布流水线。
- 文章模板、项目模板及综合测试样文。
- 开发、写作、部署、下架、备份与恢复指南。
- 验收记录、已知限制及后续需求列表。

工程验收使用测试样文完成。正式发布哪些真实文章和项目由作者决定，不强制以“三篇文章、一项项目”作为工程完成条件，也不虚构个人内容填充页面。

## 五、验收、成本与长期维护

### 5.1 必须通过的验收

**内容与功能**

- 所有主要页面、导航和空状态正常。
- 中文关键词、英文技术词及无结果搜索符合预期。
- 草稿和未来文章不出现在任何生产内容出口。
- 缺失发布状态、重复永久标识等错误能够阻止构建。
- 移动端代码、表格、公式和图表不造成整页横向溢出。
- 修改标题或移动文件不改变文章永久链接。
- 内部链接没有已知断链，404 页面有效。

**发布与恢复**

- 人为制造测试失败，确认无法发布。
- 测试通过后上传的确为被验收的同一份产物。
- 连续提交不会出现旧版本覆盖新版本。
- 可以恢复一个已知安全版本。
- 可以完成普通下架，并识别敏感撤回所需的额外处理。

**作者体验**

- 能从模板完成新建、预览、发布、修改与下架。
- 错误信息能定位到文章、字段或构建步骤。
- 能在另一环境使用备份和锁文件恢复工程。
- 指南与实际命令一致，不依赖作者记住隐含步骤。

**阅读与无障碍**

- 在 360px、768px、1440px 视口验证布局。
- 键盘可完成导航与搜索，焦点清晰。
- 无未处置的严重或致命自动化无障碍问题，并完成人工阅读检查。
- 包含中文、公式和宽架构图的真实页面具有可读性。

### 5.2 性能与 SEO 目标

在固定浏览器、测试配置和代表性页面上重复测量：

- 移动端 Lighthouse 性能目标 ≥90。
- 无障碍和 SEO 目标 ≥95。
- CLS 目标 ≤0.1。

这些是优化目标，不替代功能、安全和人工验收。单次网络波动不单独判定项目失败；持续未达标时记录原因与改进项，不宣称未验证的指标已经达成。

### 5.3 免费额度控制

- 首版使用分配的 `*.pages.dev` 地址，不默认购买域名。
- GitHub Actions 免费额度按账户共享，不能视为本项目独占。
- 日常 CI 以 Linux 和 Chromium 为主；工具链变化时补充 Windows 验证。
- 测试截图、追踪文件等优先仅在失败时保留，默认保留七天。
- 缓存依赖，取消无用的重复检查；发布任务仍遵守串行规则。
- 启用可用的费用提醒和超额限制，不自动转为付费服务。

费用目标是：**在规定的使用策略与平台免费额度内维持零固定支出，而不是承诺永久免费。**

参考：[GitHub Actions 额度](https://docs.github.com/en/billing/concepts/product-billing/github-actions)、[Cloudflare Pages 限制](https://developers.cloudflare.com/pages/platform/limits/)。

### 5.4 维护约定

- 日常通过 Git 保存内容与代码变更，每月增加一次离线备份。
- 每月检查依赖安全、构建状态、重要外链与额度使用情况；高风险安全问题及时处理，不等待月度检查。
- 记录上游版本、本项目修改点及必要补丁，不自动合并上游全部变化。
- 代码许可与文章、图片的授权分别管理。
- 本项目只接收作者控制的可信内容，不将 Markdown/MDX 当作开放投稿执行环境。

**首版完成后，默认进入“持续写作、按需改进”阶段，而不是立即扩张为复杂内容平台。**
